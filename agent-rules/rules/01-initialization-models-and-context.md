# Initialize a reproducible run

Read `agent-rules/run-config.json` (created from the example), both repository identities, base modes, task scope and source policy. Record a unique run ID and real UTC start/cutoff/completion events. Distinguish empty catalog, complete existing catalog, empty mask library, and existing mask library. All four catalog/mask combinations are valid. Existing masks retain their defining catalog digest even if a new catalog is generated.

Freeze model tags and immutable digests, tokenizer/template, Ollama/OpenCode versions, decoding/reasoning mode, rules/schema/prompt hashes, context policy, budgets, stage reservations, retry limits and optional reviewer flags. Inspect actual available backend models; never substitute an easier model without a declared change. Primary: `qwen3:235b`. Reasoning critic: `deepseek-r1:70b-llama-distill-q8_0`. Implementation specialist: `qwen3-coder-next:q8_0`.

Request 262144 tokens of context for every model. Set `OLLAMA_CONTEXT_LENGTH=262144` on the **Ollama server process**, not merely the OpenCode shell connected to an already-running server. If calling Ollama directly, request `options.num_ctx=262144`. Record the model's native context, requested value, observed allocation (`ollama ps` or equivalent serving metadata), peak GPU memory, CPU offloading, load latency, and a long-context/tool-call smoke check. A configured provider limit is not proof of backend allocation. Use sequential residency where necessary; 192 GB installed VRAM is not a single guaranteed pool.

If the target is unsupported, out of memory, truncated or unstable, keep the failure, reason and effective value. Use a reduced context only through the run's explicit fallback policy. Do not claim a 262144-token experiment from the environment variable alone. Disabled optional models do not block a core run; requested unavailable reviewers leave their configured extension incomplete. A text-only reasoning critic receives a frozen bundle without tools when native tool calls are unsupported; the coordinator handles MCP actions.

For this user's `time-limited-token-metered` CI configuration, X/Y/Z are **minutes** for question contracts, canonical solutions and per-question JSON completion. Z defaults to five minutes and also bounds each translated SF. One task deadline covers generation, deterministic checks, semantic review and repair attempts; retries never reset it. REVIEW_MINUTES caps a review within that same deadline; SOURCE_MINUTES and MASK_MINUTES bound shared tasks. Null token X/Y/R/G values mean no token ceiling was configured, not permission to invent usage or a strict token-compliance claim. Preserve raw provider usage and unavailable/overlapping reasoning/cache fields. If a later run explicitly selects token-budget mode, reserve paper X for question plus completion, Y for solutions, R for review and G for shared tasks, and require those numeric token allocations. Training and laboratory execution have separate ledgers.

Within a task, repair attempts share that task's deadline. An explicit GitHub CI rerun grants a new deadline to unfinished tasks; retain all previous attempts and reuse checked task candidates only when their prompt, source, parent and review bindings still validate. Stage checkpoints transport pinned inputs, partial outputs and Git history. In manual synthetic dry mode, model/source responses are clearly labeled fixtures; no native context, source currency, semantic acceptance or training observation is claimed from them.

Use typed states: initialized, sources-frozen, questions-accepted, solutions-accepted, fields-completed, masks-validated, core-accepted, optional-review-complete/not-requested/incomplete, published, dataset-checked, student-trained, student-evaluated, next-base-recorded. A pass state requires executed checks on exact bytes, not a manually inserted status string.
